# Drawing tab: Onshape behaviour parity checklist

One line per behaviour. Status: ✅ matches Onshape (verified in the running app and/or a test),
🔧 partly there or differs (note says how), ❌ missing, ⏳ implemented, not yet verified,
n/a only for cloud-only or multi-user behaviour (sharing, simultaneous editing). Everything else Onshape does is in scope, including MBD, versions, release / revision workflows.

Sources: `H:<page>` = Onshape help page `/root/onshape-research/docs-raw/md/Drawing__<page>.md`
(`H:Home__…` pages keep their prefix); live captures in `/root/onshape-research/live/drawing/` win
over the help pages when they differ. Code notes cite files relative to `crates/`.

Behaviour code: app `crates/app/src/drawing_view.rs` (tab, toolbar, menus), `drawing_tools.rs`
(input, tools), `drawing_ui.rs` (chrome, panels, export), `drawing_extra.rs`, `drawing_more.rs`,
`drawing_scene.rs`; model `crates/model/src/drawing/*`. Handoff: `docs/handoff/drawing-behaviour.md`.

First audit (2026-10-18, code reading): 28 ✅, 142 🔧, 188 ❌, 7 n/a of 365.
